## 1. 第一关：求职目标（选战场）

### 2026 市场结构

| 数据 | 含义 |
|---|---|
| 要求 **3 年以上经验**的岗位 **>70%** | 存量岗位"去初级化" |
| 面向 **1 年以内新人**的岗位 **-20%** | 执行层在被 AI 替代 |
| AI 相关岗位需求 **+12 倍**；部分赛道初级岗 **-20%~-30%** | 增量全在 AI 落地侧 |
| 字节 AI 全产业链新增 **4100+ 岗位**，占新增 **50%** | 资源向 AI 集中 |
| 应届 AI 工程师起薪 **17,038 元** | AI 岗溢价明显 |

来源：[定焦One · 35岁职场人又好找工作了？](https://m.21jingji.com/article/20260629/herald/15306038d66b3412d3a8deed53b1ae9b.html)

> **结论：企业不再"招人补执行"，而是"招人补 AI 覆盖不了的判断力"。** 这对 37 岁是结构性利好——前提是你能证明判断力。

### 三个方向（按匹配度排序）

| 方向 | 为什么匹配我 | 薪资参考 |
|---|---|---|
| **FDE（前沿部署工程师）** | 既要懂代码又要懂业务、能进客户现场；正是"开过的会、踩过的坑"变现 | 字节 3.5–7 万/月·15 薪；蚂蚁数科 4–6 万；智谱 6–8 万 |
| **AI 落地 / Agent 工程** | 已有 Claude Code + DSH + 脚本流水线实战 | 大厂 P7 档 |
| **投研 / 量化数据工程** | ThinkingDoing 系统本身就是作品 | 券商 / 私募 / 金融科技 |

> **FDE 的定位**（Palantir 定义）：*"传统研发是为很多客户做一个能力，FDE 是为一个客户启用很多能力。"*
> 它要的不是年轻和能熬夜，而是**能翻译业务、能判断风险、能对结果负责**。

### 第 1 关通过判据

> **能用一句话说清「为什么这个岗位非我不可」。说不出来，就还没过关。**

**我的答案（草稿，需按目标岗位改写）**：

- 对 **投研数据**：「我有一套自己跑了 100+ 天的投研系统，从数据抓取到纪律诊断到复盘生成，全链路自动化。」

## 2. 第二关：简历（6 秒定生死）

### 一页结构

```
① 一句话定位：我是谁 + 我最擅长解决什么问题
② 3–4 个成果（量化：从 X 到 Y，节省 Z）
③ 技术栈（只写能聊 20 分钟的，5–8 个）
④ 经历（最近 8–10 年，越近越详细）
⑤ 作品链接（GitHub / 站点）
```

### 我的简历素材（从仓库提取，可直接用）

| 原始事实 | 简历写法 |
|---|---|
| 每日复盘 60 分钟手动 | **「把每日复盘从 60 分钟压缩到 1 条命令，累计 100+ 天无缺勤」** |
| 12 个脚本 3,288 行 | 「独立设计并实现 12 个模块的行情数据管线（Python + SQLite）」 |
| 123 篇 docs + 103 篇 review | 「构建 200+ 篇结构化知识库，VitePress 自动构建部署」 |
| 5 项自动校验 | 「设计 5 项自洽性校验，替代人工价格比对，消除数据错位风险」 |
| 多源数据优先级（华泰 > 问财 > 腾讯） | 「制定三级数据源容灾策略，明确禁用不稳定来源」 |
| SQLite 数据仓库 + 迁移 | 「设计行情数据仓库（4 张表）+ 历史数据迁移方案」 |

### 三个致命写法（改掉）

| ❌ 错误 | ✅ 改法 |
|---|---|
| "负责 XX 系统的开发与维护" | "把 XX 发布周期从 2 天压到 2 小时（CI + 自动化测试）" |
| 罗列 20 个技术名词 | 只留 5–8 个，每个配一句"用它解决过什么" |
| 写 15 年全部经历 | 只写最近 10 年，早期一行带过 |

### 37 岁的特殊处理

**把「年限」翻译成「复杂度」**：

> ❌ "10 年 Java 开发经验"
> ✅ "主导过 3 次单体到微服务迁移，其中一次在不停机前提下完成 2000 万用户切换"

**年限是成本，复杂度是资产。** 招聘方看到"10 年"想到"贵"，看到"不停机迁移"想到"能扛事"。

### 第 2 关通过判据

> **找个不懂你行业的人看 6 秒，他能说出「这人是干什么的」。**

## 3. 第三关：面试（考判断力）

### 权重

| 类型 | 占比 | 考什么 |
|---|:--:|---|
| **项目深挖** | ~60% | 判断过程与取舍 |
| 技术基础 | ~25% | 地基 |
| 行为/动机 | ~15% | 稳定性、协作 |

### 四个必答题（提前写好，背熟）

1. **最难的技术决策是什么？有哪些选项？为什么选这个？**
2. **做过的最失败的一件事？根因是什么？**
3. **如果重做一次，你会怎么改？**
4. **这个项目里，哪些是你做的、哪些是别人做的？**（考诚实）

> **第 2 题是分水岭。** 答"没失败过"或"失败是别人的问题"，基本出局。
> 正确结构：**我误判了 X → 代价是 Y → 后来我改了 Z，让这个错不可能再发生。**

### AI 时代的必答题（2026 年必考）

据猎头反馈，面试官**不问"用没用过 AI"**，而是直接问：

> **"你当时用 AI 做了什么？效果是什么？产出提升了多少？"**

只答"用过" = 这轮到头。我的标准答案模板：

```
我做了：把复盘流程从「手动抓数据 + 手填模板」改成「脚本抓取 + AI 分析」
效果：  每日耗时 60 分钟 → 约 5 分钟
产出：  100+ 天连续产出，且加了 5 道自动校验，把数据错位风险降到 0
```

### 我的 5 个故事（骨架，细节待填）

#### 故事 1：把复盘从 60 分钟压到 1 条命令

| 要素 | 内容 |
|---|---|
| 背景 | 每天收盘后手动抓数据、算指标、填模板，60 分钟 |

| 代价 | `___`（例如：初期脚本不稳定，某次抓错数据导致复盘结论偏差） |
| 结果 | 一条命令产出模板，100+ 天连续执行 |
| 反思 | `___` |

#### 故事 2：一张会腐烂的核对表 ⭐ 最推荐优先讲

| 要素 | 内容 |
|---|---|
| 背景 | 有一张硬编码的价格区间表，用来人工核对数据有没有串价 |
| 判断 | 上证从 3000 走到 3730 后，15 项里 13 项"超出区间"，但无一真的串价 |
| 根因 | **问题不在表，在"用绝对值做校验"这个设计**——绝对价格会随行情漂移 |
| 方案 | 改成不比绝对值，只比 5 条在任何点位都成立的自洽关系（字段自洽/数据新鲜/量级/历史跳变/均线偏离） |
| 结果 | 检查项从"每天要人比对"变成"自动跑、退出码判断"，且能真正抓到串价 |
| 反思 | **一个长期不更新却每天要人核对一遍的检查项，最终会训练人忽略它** |

> 这个故事能同时证明：**系统思维 + 根因分析 + 工程判断 + 对"人肉流程"的警惕**。是我最有差异化的素材。

## 4. 第四关：薪酬（谈结构）

### 时机

| 阶段 | 正确动作 |
|---|---|
| HR 电话初筛 | **不报数字**："我对总包有预期，但更想先了解岗位范围" |
| 技术面通过后 | 可给区间 |
| **拿到书面 offer 后** | 这才是真正的谈判起点 |

### 算总包，不算月薪

```
总包 = 基本工资 × 月数 + 绩效 + 年终 + 股票/期权 + 签字费 + 补贴
```

**三年总包**才是可比数字。"月薪高 10% 但 13 薪"可能不如"月薪低 5% 但 16 薪 + 股票"。

### 谈判三条

1. **给区间，下限 = 你的目标**。说"35–42 万"，对方一定给 35。
2. **用竞品 offer 做锚**，但别虚构（会被背调）。
3. **非现金项也能谈**：远程天数、入职时间、签字费、职级。

> **职级比月薪重要**——它决定未来三年的涨薪天花板。

### 第 4 关通过判据

> 拿到书面 offer，且清楚三年总包的每一块钱来自哪。

## 5. 第五关：试用期（前 90 天）

### 30 / 60 / 90

| 阶段 | 目标 | 关键动作 |
|---|---|---|
| **0–30 天** | 搞清规则 | 问清"谁决定我留不留""什么叫做好了"；**读代码不改造** |
| **30–60 天** | 交付小胜利 | 挑一个边界清晰、能独立完成、对别人有价值的事 |
| **60–90 天** | 建立信任 | 主动汇报进展和风险，别等被问 |

### 三个保命原则

1. **别急着改历史代码。** 有人入职后发现团队"一直让 AI 改代码"，两个文件堆到几千行、结构混乱，凌晨上线失败——**问题在于没人能管住 AI**。前 30 天只读不改。
2. **先搞清楚"谁的评价算数"。** 直属领导？跨部门对接人？搞错对象，干得再多也白搭。
3. **风险要早报。** "我可能延期"在第 10 天说 = 负责；在第 80 天说 = 失职。

### 第 5 关通过判据

> 第 60 天能独立交付一件别人看得见的事。
