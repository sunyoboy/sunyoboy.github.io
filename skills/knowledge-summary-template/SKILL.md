# 知识总结

## 使用场景

1. **周报生成**：汇总本周 5 篇日复盘 → P→D→C→A 四段
2. **笔记整理**：把日报中重复出现的教训沉淀为规则（周六深度块/月度回顾用）
3. **主题汇总**：按关键词扫描 review/ + questions/ + growth/，输出结构化总结

## 规则来源（必须遵循）

所有输出遵循 `docs/report-note-sop.md`：

- **日报规则 D1–D7**：结构不跳项、学到≠流水账、明日计划可执行
- **周报规则 W1–W6**：只引用日报数字不重算、C 是核心、下周 ≤3 件
- **笔记规则 N1–N6**：沉淀判据（复现≥2次/可迁移/可执行）→ 路由表分流 → 三段式格式

## 执行流程

1. **确定范围**：周报=本周 `review/YYYY/MM/` 下 5 篇日报；主题汇总=指定关键词或目录
2. **逐篇提取**：按周报数据提取映射表取数（盈亏=末日累计−上周累计；教训=挑影响最大 1–2 条）
3. **汇总输出**：周报按 P→D→C→A；笔记按三段式模板（规则/来源/验证/反例）
4. **沉淀分流**：候选笔记逐条过 N1 判据 → 查路由表 → 指出应更新哪个文件
5. **联动提示**：输出末尾列出需要同步更新的 catalog.md / config.mjs 条目

## 总结

1. 内容结构化整理，遵循金字塔原理
2. 周报 C 部分（偏差归因 + 如果重来）必须填写，不允许跳过
3. 笔记宁缺毋滥：三条判据都不满足的，明确说"留在日报，不沉淀"

## 输出

1. 给出定义（抽象）或含义
2. 给出应用场景分类
3. 输出简明扼要的总结 + 沉淀队列（如有）
