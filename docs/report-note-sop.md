# 日报 · 周报 · 笔记整理 规则总纲

> 三层输出体系：**日报记事实 → 周报做提炼 → 笔记做沉淀**。
> 本文件是规则总纲——日报流程细节见 [每日复盘SOP](daily-review-sop)，周报骨架见 [个人周报模板](../growth/个人周报模板)，笔记沉淀规则唯此一份。

---

## 一、三层体系总览

```
每日（原始层）              每周（提炼层）                长期（沉淀层）
────────────              ─────────────               ─────────────
日复盘 review/YYYY/MM/    周复盘 review/YYYY/MM/       docs/ 知识文档（规则化）
问题清单 questions/   →   个人周报 growth/（P/D/C/A）→  growth/ 方法论 / OKR
持仓存档 portfolio/       飞轮审计（周检查清单）          纪律文档 / scripts/ 自动化
```

**四条总原则**

1. **原始事实只记一次**——数字、事件、操作只写在日报里，周报/笔记只引用不重算，避免口径分叉。
2. **提炼看趋势，沉淀看复现**——周报回答"这周怎么样"，笔记只收"重复出现 ≥2 次、跨场景可复用"的东西。
3. **每层有自己的模板和门禁**——写之前先看本层检查清单，不跳项。
4. **新文件 → 必更新 catalog.md + config.mjs**——提交前三查（sidebar / catalog / build），7/28 漏菜单 12 个 commit 才发现的教训。

## 二、日报规则（每日 15:00-16:00 · 🔋🔋 中能量）

| # | 规则 | 说明 |
|:--:|------|------|
| D1 | **时机固定** | 收盘后 1 小时内完成，不拖到晚间（晚间是低能量维护时段） |
| D2 | **数据先行** | 先跑 `generate-review.py`（或三脚本）拿到数据稿，再人工补分析 |
| D3 | **核对门禁** | 价格核对（防串价）不通过 → 不开写。宁可多花 2 分钟，不要全文订正 |
| D4 | **结构不跳项** | 按日报模板逐项填：指数表现 → 盘面特征 → 今日驱动 → 热门板块 → 资金流向 → 技术面 → 后市关键 → 做了什么 → 持仓盈亏 → 学到了什么 → 明日计划 |
| D5 | **学到 ≠ 流水账** | "学到了什么"至少 1 条，写成"因为…所以…"的因果句，禁止"今天涨了/跌了" |
| D6 | **明日计划可执行** | 必须有具体标的 + 价格 + 触发条件；写不出的就写"不做清单" |
| D7 | **联动更新** | catalog.md + config.mjs 侧边栏 + （如有）问题清单 index |

> 详细流程（7 步流水线 · 检查点 · 异常处理）→ [每日复盘SOP](daily-review-sop)

### 日报一句话导语（模板）

```markdown
# YYYY-MM-DD
> **收盘复盘**（15:00 后定稿）· 数据源：腾讯行情 + 申万行业监测 + 公开收评
> 🔴 **一句话**：<今天最重要的一件事，30 字内，带数字>
```

## 三、周报规则（周日 14:00-17:00 · 🔋🔋 收尾块）

| # | 规则 | 说明 |
|:--:|------|------|
| W1 | **时机固定** | 周日收尾块，30 分钟内完成初稿（初稿可周六下午起） |
| W2 | **只引用不重算** | 全部数字从本周 5 篇日报提取，发现口径矛盾 → 回日报改，不在周报里"修正" |
| W3 | **结构 P→D→C→A** | 按个人周报模板四段走，C 是核心（偏差归因 + "如果重来"必填） |
| W4 | **交易周报单独出** | 有交易周 → `review/YYYY/MM/YYYY-WNN.md`（市场回顾 / 交易回顾 / 经验教训 / 下周计划） |
| W5 | **沉淀触发** | C 部分发现重复教训 → 立刻记入"笔记沉淀队列"，周日不展开写，留给笔记整理时段 |
| W6 | **≤3 件下周大事** | 下周计划最多 3 件最重要的，写多了等于没写 |

### 周报数据提取映射表（从日报到周报）

| 周报字段 | 从日报哪里取 | 提取方法 |
|------|------|------|
| 本周盈亏 | 每日"持仓盈亏" | 末日累计 − 上周五累计 |
| 胜率 / 做T次数 | 每日"做了什么" | 逐日点数汇总 |
| 最大教训 | 每日"学到了什么" | 挑影响最大 1–2 条，其余留给月回顾 |
| 下周计划 | 每日"明日计划" | 合并去重 → 按优先级砍到 ≤3 |
| OKR 进度 | growth/年度OKR | 逐 KR 填当周实际值，不留空白 |

## 四、笔记整理规则（沉淀 · 周六深度块 / 月度回顾）

> **这是日报到知识库的升级通道。** 没有这一层，日报写得再好也只是日志，三年后什么都留不下。

### 沉淀判据（N1 · 三选一才允许升级为笔记）

1. **复现**：同类教训在日报里出现 ≥ 2 次（引用具体日期）
2. **可迁移**：跨场景成立，不绑定单一标的 / 单一日期 / 单次行情
3. **可执行**：能写成"如果 <条件>，就 <动作>"的规则语句

> 三条都不满足 → 留在日报里，不硬沉淀。**宁可漏收，不可滥收**——笔记一多，等于没有笔记。

### 路由表（N2 · 什么内容去哪个文件）

| 内容类型 | 触发信号 | 去向 |
|------|------|------|
| 交易纪律 / 止损教训 | 同类错误 ≥2 次 | 更新 [position-discipline](position-discipline) 或 [ma5-deviation-discipline](ma5-deviation-discipline) 对应章节 |
| 新策略 / 新方法论 | 已在日报中验证过效果 | `docs/` 新建专题（`strategy-*.md` / `trading-*.md`） |
| 认知偏差 / 心态 | 复盘中反复出现的情绪模式 | `docs/mindset.md` 或 growth/方法论 |
| 待验证问题 | 需要后续数据 / 事件确认 | `questions/YYYY/MM/` 对应日期文件 |
| 宏观 / 市场事实 | 月度级别数据 | `review/YYYY/MM/` 月度市场概况 |
| 重复手工操作 | 同一动作手动做了 ≥3 次 | 写成脚本进 `scripts/` + 更新 [tech-stack](tech-stack) |

### 沉淀格式（N3 · 三段式，可直接复制）

```markdown
## <规则名>

**规则**：如果 <触发条件>，就 <动作>。
**来源**：[YYYY-MM-DD 复盘](../review/YYYY/MM/YYYY-MM-DD) · [YYYY-MM-DD 复盘](../review/YYYY/MM/YYYY-MM-DD)
**验证**：首次发现 2026-MM-DD，第 N 次复现 2026-MM-DD（<一句话事实>）
**反例**：<哪次没遵守、代价是什么>（无则删此行）
```

### 整理动作清单（N4–N6）

- [ ] **N4 原文不删**：日报是原始记录，笔记里只放链接，不搬运正文
- [ ] **N5 联动更新**：新文档 → catalog.md + config.mjs；规则类 → 顺手更新对应纪律文档的条款（而非另开新文件）
- [ ] **N6 时机固定**：只在周六深度块或月度回顾时做整理，不占用工作日高能量时段
